# 真实模型回归与优化前后性能对比

测试日期：2026-10-15。四个缺失模型已下载并校验；40 项测试全部通过，分词和词性标注共 234 条逐句输出与优化前一致。性能收益最明确的是临时内存分配减少，以及词性标注在回归语料、短文本和长文本上的吞吐量提高。

## 模型与回归

模型取自 THUNLP 的 [thulac 0.2.2 PyPI 发行包](https://pypi.org/project/thulac/0.2.2/)，使用其 wheel 内的 CWS 和 POS 模型。压缩包 SHA-256 已与 PyPI 公布值核对，全部文件尺寸和 SHA-256 见 [模型清单](../models/manifest.json)。四个二进制模型合计 493,400,720 字节；两个标签文件与仓库原文件逐字节一致，模型尺寸与原有测试预期一致。大模型文件保持 Git 忽略。

- `mvn -o -B -ntp -Pmodel-tests test`：40 项测试，0 失败、0 错误、0 跳过；真实模型测试保持原有预期断言。[运行日志](results/2026-10-15/regression.log)
- 使用同一套模型和配置，独立运行优化前后两个版本，分词 117/117、词性标注 117/117 条输出完全一致。[核对结果](results/2026-10-15/output-equivalence.json)
- 语料取自仓库已有的 `SegmenterTest.SENTENCES`，保存在 [corpus.txt](corpus.txt)，共 117 条（包含空串和空白边界用例），共 1,420 个字符。这是仓库现有回归覆盖，不是新下载的大规模标注评测集，不能据此宣称整体准确率提升。

## 对比方法

优化前为 Git 提交 `a9d5b8405e71ff900be08f36b876c225daec63c7` 的原始生产代码，优化后为本次工作区的生产代码。两版使用相同 Maven 配置、JMH 测试程序、模型和词典；优化前代码在独立目录编译，未修改工作区或重置 Git。优化后源码逐文件 SHA-256 已记录在 [环境记录](results/2026-10-15/environment.json) 中。

测试机器为 Apple M2 / Mac14,2，16 GiB 内存，macOS arm64（Darwin 25.6.0）。运行时使用 Oracle JDK 19.0.1，固定 `-Xms2g -Xmx2g -XX:+UseG1GC`，JMH 单线程、2 个独立 JVM，每个 JVM 预热 3 次、测量 5 次，每次 1 秒。按场景交替两版执行顺序，保留所有测量值，没有剔除慢样本。构建输出为 Java 8 字节码；本次实际性能测量只覆盖 JDK 19。

模型加载不计入稳态吞吐量。117 句语料每次批量处理，JMH 使用 `@OperationsPerInvocation(117)` 归一化，所以吞吐量单位为句/秒，分配量为每句字节数。短文本为 18 字符，中英混合为 46 字符，长文本为短文本重复 200 次（3,600 字符），后者属于合成长输入。回归语料开启书名词规则，与原回归配置一致；另外三种输入使用默认配置。

## 模型初始化与峰值内存

每个模式、每个版本均启动 5 次全新 JVM，交替执行，采用相同 JDK、堆和 GC 参数；下表是中位数。初始化耗时仅计分词器构造（包括模型与所需词典加载），不含 JVM 启动。峰值 RSS 由 macOS `/usr/bin/time -l` 记录，涵盖整个进程（含 JVM、构造以及计时区间外的一次“测试”分词），不能等同于 Java 堆存活对象大小。

| 模式 | 初始化：优化前 → 优化后 | 耗时减少 | 峰值 RSS：优化前 → 优化后 | 峰值减少 |
| --- | ---: | ---: | ---: | ---: |
| 分词 | 107.1 → 60.3 ms | 43.7% | 612.9 → 163.3 MiB | 73.4% |

未清空文件系统缓存，因此这是新 JVM 初始化测试，不是冷磁盘读取测试。词性标注基线的首个样本约 630 ms，其余约 261–320 ms；全部样本均保留，中位数约 271 ms。[逐次样本](results/2026-10-15/loading-samples.json)

## 复现与原始数据

需要 Python 3.8+、curl、Maven，以及支持 `--release` 的 JDK（建议用同一 JDK 19.0.1 重现本次结果）。在仓库根目录执行：

```sh
python3 scripts/download_models.py
mvn -Pmodel-tests test
python3 benchmarks/compare.py --java /path/to/jdk-19/bin/java
python3 benchmarks/check_outputs.py
python3 benchmarks/measure_loading.py
python3 benchmarks/summarize.py
```

`compare.py` 自动构建两版并顺序运行完整 16 组测量，默认基线为上文提交，结果写入 `target/performance/`。输出核对与加载探针必须在构建和吞吐量测量完成后顺序执行，避免争抢资源。`measure_loading.py` 的峰值 RSS 统计仅支持 macOS，受限环境需允许读取系统资源统计。测量期间应避免其他高负载活动。

本次持久化数据位于 [results/2026-10-15](results/2026-10-15/)：16 份 JMH JSON（包含每个 JVM 的原始测量）、环境和源码哈希、[汇总](results/2026-10-15/summary.json)、加载样本、逐句输出及回归日志。可以只重新生成汇总：

```sh
python3 benchmarks/summarize.py --input benchmarks/results/2026-10-15
```

结论适用于上述模型、语料、硬件和运行参数；本次没有测量多线程吞吐、其他 JDK 或线上尾延迟。
